**src/components/features/gallery/PlayerControls.tsx:**

Create first-person controls combining PointerLockControls (mouse look) and WASD movement with collision:

- Import useFrame and useThree from @react-three/fiber
- Import useKeyboardControls and PointerLockControls from @react-three/drei
- Import THREE (Vector3 only needed)
- Import clampToRoom, ROOM_CONFIG from ./constants

Movement logic in useFrame (called every frame):
1. Get key states via `getKeys()` from useKeyboardControls (use the functional form: `const [, getKeys] = useKeyboardControls()`)
2. Calculate movement direction relative to camera facing:
   - frontVector: (0, 0, Number(backward) - Number(forward))
   - sideVector: (Number(left) - Number(right), 0, 0)
   - direction = subVectors(frontVector, sideVector).normalize().multiplyScalar(MOVE_SPEED * delta).applyEuler(camera.rotation)
3. Compute candidate position: newX = camera.position.x + direction.x, newZ = camera.position.z + direction.z
4. Call clampToRoom(newX, newZ, camera.position.x, camera.position.z) to get clamped position
5. Apply clamped position to camera.position.x and camera.position.z
6. ALWAYS reset camera.position.y to ROOM_CONFIG.eyeHeight (prevents flying from pitch+movement)

MOVE_SPEED = 5 (feet per second -- comfortable walking pace in a gallery)

Create direction/frontVector/sideVector as module-level constants (outside useFrame) to avoid GC pressure. Do NOT create new Vector3 instances inside useFrame.

Render PointerLockControls as the component's return value. No props needed -- it auto-uses the default camera.

IMPORTANT: Do NOT use `'use client'` in this file. It is imported by GalleryScene which is dynamically imported by a client component, so it is already in the client bundle.

CRITICAL: KeyboardControls MUST wrap Canvas, NOT be inside it. This is a known pitfall from the research.

The Canvas should be wrapped in a div with className="h-screen w-screen" (this may already come from GalleryClient, but ensure the Canvas fills the viewport).

Set the camera's initial lookAt toward the center of the room. Since PointerLockControls overrides rotation on lock, the initial camera rotation should face north (negative Z). Use `rotation={[0, Math.PI, 0]}` on the camera OR set the camera position and let PointerLockControls handle look direction. Actually, the simplest approach: set camera position at START_POSITION and let the user click to activate pointer lock -- the initial view will show whatever is in front of the camera's default forward direction (negative Z), which is correct since that's looking into the room.

Wait -- default camera looks down -Z which is INTO the room (north). START_POSITION has z=-1.0. Looking down -Z means looking at z=-23 (north wall). This is correct -- the user starts at the entrance looking into the room.
